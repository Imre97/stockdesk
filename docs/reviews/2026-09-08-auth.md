## Findings

### Blockers

- `apps/api/src/app.ts:35` — `rateLimit()` keys on `req.ip` but the app never sets `trust proxy`; on Render every request arrives from the platform proxy, so the documented "10 requests per 15 minutes per IP" becomes 10 per 15 minutes for all clients combined (and express-rate-limit v7 emits `ERR_ERL_UNEXPECTED_X_FORWARDED_FOR`). Set a fixed hop count (`app.set("trust proxy", 1)`), never `true`, and cover it with a test that sends `X-Forwarded-For` from two addresses and expects two independent buckets.
- `apps/api/src/modules/auth/repository.ts:97-111` — the rotation transaction reads the row with `findUnique` (plain `SELECT`, no row lock) and revokes with `update({ where: { id } })`, which has no `revokedAt` predicate. Under the default READ COMMITTED isolation two concurrent `/refresh` calls presenting the same cookie both observe `revokedAt: null`, both revoke, and both insert a new token: one presented token yields two live refresh tokens and reuse detection never fires. Change the revoke to `updateMany({ where: { id: presented.id, revokedAt: null } })` and treat `count === 0` as `{ status: "reused" }`; add a test that fires two `/refresh` calls with the same cookie in parallel and asserts exactly one 200 and one `REFRESH_REUSED`.

### Should fix

- `packages/shared/src/decimal.ts:22` — `toApiString(value: DecimalValue | string | number, ...)` accepts a native `number` for the money serializer, and `packages/shared/src/decimal.test.ts:124` locks that overload in. Narrow the parameter to `DecimalValue | string` and delete the number case from the test so later modules cannot serialize a float.
- `apps/api/src/modules/auth/cookies.ts:13` and `apps/api/src/modules/auth/tokens.ts:18,29,48` — these read the `getConfig()` singleton, so `createApp({ config })` only affects the rate limiter; cookie `secure`, JWT secret/TTL and refresh TTL silently ignore the injected config. Thread the config through (factory or explicit argument) or drop the `config` option to stop implying isolation it does not provide.
- `apps/api/src/app.ts:58-61` — no terminal handler on `/api/v1`, so an unknown API path returns Express's default HTML 404 instead of the `{ "error": { "code", "message" } }` envelope required by `docs/02-conventions.md`; `apps/api/src/static-web.test.ts:53-56` asserts that HTML 404 as expected behavior. Add a JSON `NOT_FOUND` handler after the API router and assert the envelope.
- `apps/api/prisma/schema.prisma:26-34` — `RefreshToken` rows are never deleted; every login and every refresh inserts one and only flips `revokedAt`. With Neon free at 0.5 GB and a 7-day TTL this grows without bound. Add a pruning path (delete rows with `expiresAt < now()` on boot and on each rotation) and a test.
- `apps/api/test/auth.refresh.test.ts:52-54` — `expect(["UNAUTHORIZED", "REFRESH_REUSED"]).toContain(...)` accepts two different behaviors for a deterministic case (the rotated token was revoked by reuse detection, so it must be `REFRESH_REUSED`). Assert the single expected code.
- `apps/api/test/health.test.ts:8-14` — only the 200 branch is tested; the spec's `503` with `"database": "unreachable"` (`apps/api/src/modules/health/router.ts:11-13`) has no test. Inject a failing query or stub the client and assert status 503 and the body.
- `eslint.config.js:62` — `sourceGlobs` covers `apps/api/src/**`, `apps/web/src/features/**`, `packages/shared/src/**`, leaving `apps/web/src/lib/**`, `apps/web/src/routes/**` and `apps/web/src/components/**` free to call `Number()`, `parseFloat` and `.toFixed()` on money. Widen to `apps/web/src/**` before Module 2 puts formatting in `lib/`.
- `docs/modules/auth.md:67,143-159,161` — the spec does not record what the code does: `VALIDATION_ERROR` returns `422` (`apps/api/src/middleware/error-handler.ts:29`), the 503 health body is `{ "status": "degraded", "database": "unreachable" }`, and `WEB_DIST_DIR` is a required-by-default variable present in `.env.example` but absent from the spec's environment block. The code is right; update the spec.

### Nice to have

- `apps/api/src/modules/auth/repository.ts:100` — expiry is checked before revocation, so replaying an expired-and-already-revoked token returns `UNAUTHORIZED` and does not revoke the session set. Check `revokedAt` first if reuse detection should win over expiry; either way state the ordering in the spec.
- `apps/api/src/lib/config.ts:71` — `resetConfigCache()` has no caller and no test. Remove it.
- `apps/web/src/features/auth/hooks.ts:42` — `useRequireAuth()` returns `{ user, status }` and requires nothing (the guard lives in `features/auth/guard.ts`); it has no consumer. Rename it or drop it and reconcile with the spec's frontend file list.
- `apps/web/src/features/auth/store.ts:84-94` — `configureHttp(...)` runs as an import side effect, so HTTP behavior depends on whether the store module was imported. Wire it from the app entry point instead.
- `apps/api/src/modules/auth/service.ts:10` — `bcrypt.hashSync` at module load blocks the event loop for roughly a cost-12 hash on every boot, including Render cold starts. Compute it lazily on first use.
- `apps/api/src/modules/auth/tokens.test.ts:56-60` — `refreshTokenExpiry` is only asserted to be "greater than now"; it never proves the 7-day `REFRESH_TOKEN_TTL_DAYS` offset. Assert the exact millisecond offset from a fixed date.
- `apps/e2e/playwright.config.ts:41-56` — e2e runs the Vite dev server with `NODE_ENV=test`, so the production path (`helmet` CSP + `express.static` + SPA fallback + one-origin cookie) is never exercised end to end; `apps/api/src/static-web.test.ts` mounts `mountStaticWeb` without helmet. Add one e2e project that serves the built web from the API.
- `apps/web/src/features/auth/components/LoginForm.tsx:5-7` — raw palette classes (`text-red-700`, `bg-neutral-900`) instead of CSS-variable tokens, and no `.dark` variant. Explicitly deferred by the spec's styling note; register as debt so it is not forgotten.

## Optimization opportunities

- `apps/api/prisma/schema.prisma:26-34` — `RefreshToken` has no index on `userId`, but reuse detection runs `updateMany({ where: { userId, revokedAt: null } })` (`repository.ts:103`) and cascade delete uses `userId`. Add `@@index([userId])`; removes a sequential scan per reuse event. Now, in the same additive migration as the pruning change.
- `apps/api/src/modules/auth/service.ts:57` — the `findUserByEmail` pre-check is redundant with the `P2002` handler at `:70`, costing one extra round trip on every registration (about 500 ms on a cold Neon compute). Drop the pre-check and keep the P2002 path. Now.
- `apps/web/src/i18n/index.ts:3-7` — both `en` and `hu` catalogs are statically imported into the main chunk; every future namespace doubles. Switch to dynamic import per locale before the namespace count grows. Next module.
- `apps/api/src/app.ts:55` — `express.json()` uses the 100 kb default for endpoints whose largest body is three short strings. Set an explicit small limit (for example `{ limit: "16kb" }`) to cap parse work on the 512 MB instance. Later.
