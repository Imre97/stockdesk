## Findings

### Blockers

- none.

### Should fix

- `apps/web/src/features/auth/session-reset.ts:20` — `useSettingsStore.reset()` routes through `change()` (`apps/web/src/features/settings/store.ts:38-42,73`), which persists the whole in-memory state; `hydrateFromCache` runs only inside `bootstrapAuthenticatedApp`, so on the login page, on anonymous boot (`apps/web/src/features/auth/guard.ts:8` → `clearSession`) and after a wrong-password login (`apps/web/src/features/auth/store.ts:48`) the cached `{ language: "hu", theme: "dark" }` is rewritten to `{ "en", "system" }`; recovered only at the next successful login. Fix: make `reset()` clear `defaultAccountId` in the cache without rewriting language/theme (read the cache, patch that one field), or hydrate before resetting. → TD-31

### Nice to have

- `apps/web/src/features/auth/hooks.ts:32-33` — `logout()` already resets via `clearSession`, so the hook's second `resetClientState` is redundant; keep one call site so the reset cannot diverge between the logout and expiry paths. → TD-33
- `apps/web/src/features/shell/hooks.ts:78-92` — the `account_summary` socket is closed only by layout unmount, so a message arriving between `resetClientState` and the `/login` navigation re-populates the outgoing user's accounts via `applyAccountSummary`; disconnect explicitly on session reset. → TD-32

## Optimization opportunities

- `apps/web/src/features/settings/sync.ts:13-20` — `["settings"]` is not user-scoped; keying it by `user.id` would make the cache self-invalidating and remove the reliance on `queryClient.clear()` ordering. Next module. → TD-34

## Tech debt candidates

- Settings cache overwritten with defaults when `resetClientState` runs before `hydrateFromCache` (login page, anonymous boot, failed login).
- Duplicate reset call sites: `useLogout` plus `clearSession`.
- WebSocket not disconnected by the session reset, only by layout unmount.
- Query keys not user-scoped (`["settings"]`), correctness depends on the cache clear.
- No e2e coverage for "second user in the same tab" and for preference survival after an expired session.
